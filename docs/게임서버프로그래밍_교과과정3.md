# 게임 서버 프로그래밍 취업 교과과정

본 교과과정은 국내 게임 개발사의 신입·주니어 게임 서버 프로그래머 채용에서 요구되는 핵심 역량을 기준으로 구성하였다.

NCS는 직무 요소의 누락 여부를 확인하는 기준으로 활용하고, 실제 교과 내용은 게임 서버 프로그래머 취업에 필요한 C++ 서버 구현 역량을 중심으로 구성한다.

## 1. 교육 방향

### 출발점
- C 언어를 이수한 학생
- C++은 아직 학습하지 않은 상태

### 목표 수준
게임 서버 프로그래머 취업을 목표로 하며, 단순 입문 수준을 넘어 **실무 경력 1~2년차 게임 서버 프로그래머가 다루는 핵심 기술을 이해하고 구현할 수 있는 수준**을 지향한다.

실제 라이브 서비스 경력 자체를 교육으로 대체할 수는 없으므로, 학교에서는 다음을 목표로 한다.

- C++ 기반 서버 프로그램 설계 및 구현
- 운영체제, 스레드, 네트워크 I/O 이해
- 세션, 패킷, 버퍼, 작업 큐 기반의 게임 서버 코어 구현
- 데이터베이스 연동과 영속 데이터 처리
- Unreal 및 Unity 클라이언트와 서버 연동
- MORPG/MMORPG 서버 구조 이해
- 서버 성능과 병목의 기본 분석
- 오픈소스 서버 구조를 읽고 자신이 만든 서버와 비교할 수 있는 능력

### 교육 원칙
- 학교에서는 **기초와 구현 과정**을 중심으로 교육한다.
- 모든 실무 기술을 교과과정에 넣지 않는다.
- 심화 기술은 프로젝트 또는 자율학습으로 확장한다.
- C++ 서버 코어가 중심이며 Unreal과 Unity는 서버를 적용하고 검증하는 환경으로 활용한다.
- 세 목표 과업은 서로 독립된 프로젝트가 아니라 이전 단계의 기술을 누적하여 발전시킨다.


### 교과과정 핵심 원칙

-  **NCS는 교과과정의 점검 기준으로 활용**
- 교과과정은 서버 프로그래머에게 반드시 필요한 기초와 구현 능력을 중심으로 구성
- 게임 네트워크 프로그래밍은 **기초 과정**, 게임 서버 프로그래밍은 **응용 구현 과정**으로 구분
- 디자인 패턴은 면접과 실제 서버 설계를 위해 **필수 과정**으로 포함
- Windows를 주 실습 환경으로 사용하며 Linux 운영, Docker, 클라우드, CI/CD는 선택 학습으로 분리
- Redis와 MongoDB는 현업 활용을 고려하여 **필수 데이터베이스 기술**로 포함
- C++ 서버 코어가 중심이며 Unreal과 Unity는 서버 기술을 적용하고 검증하는 환경
- C/S와 P2P를 모두 이해하되 최종 목표는 취업 방향에 맞추어 C/S 서버 구현을 중심으로 구성
- 목표 과업은 이전 단계 기술을 누적하여 발전
- IOCP, Ring Buffer, Job Queue, AOI 등 게임 서버 핵심 기술은 필요 시점에 단계적으로 도입
- Memory Pool, Object Pool, Custom Allocator는 개론 수준으로 다루고 심화 구현은 선택 학습으로 분리
- 오픈소스 서버와 네트워크 라이브러리는 자신의 구현과 비교·분석하는 선택 학습 자료로 활용
- 서버 프로그래머가 DevOps 전문가가 될 필요는 없지만 Build, Version, 배포, Rollback, CDN/HTTPS 패치의 기본 흐름은 이해
- 최종 목표는 **게임 서버를 설계하고 구현하고 분석할 수 있는 프로그래머 양성**

| 영역 | 핵심 내용 |

## 4.5 게임 네트워크 프로그래밍

### 목표
게임에서 사용하는 C/S와 P2P 네트워크 구조를 이해하고, 주력인 C/S 게임 서버의 기반을 직접 구현한다.

### 네트워크 모델

| 모델 | 과정 범위 | 본 과정에서의 위치 |
|---|---|---|
| **Client / Server** | 서버 권한, 다중 접속, Session, Packet | 핵심 |
| **P2P** | Peer/Host 구조, C/S와 차이, 장단점 | 기초 이해 및 소규모 실습 |

### P2P 과정 범위
P2P를 별도의 최종 프로젝트로 만들지는 않는다.

- Peer / Host 개념
- P2P와 C/S 비교
- Host 이탈 문제
- NAT 문제 개념
- 치팅과 권한 문제
- 2~4 Peer 간 간단한 통신 경험

> Unreal의 Listen Server는 한 클라이언트가 서버 역할을 겸하는 **Client/Server 구조**이며 P2P와 구분한다.

### C/S 서버 구현

| 영역 | 핵심 내용 |
|---|---|
| 네트워크 | TCP/IP, UDP 개념 |
| Socket | Winsock2 |
| TCP 처리 | Blocking → Non-blocking → Overlapped I/O |
| 비동기 I/O | IOCP |
| 세션 | Session |
| 패킷 | Header / Body, Packet Parser |
| 버퍼 | Send/Recv Buffer, Ring Buffer |
| 스레드 | Worker Thread |
| 작업 처리 | Thread Pool, Job Queue |
| 연결 관리 | Connect, Disconnect, Timeout |
| 안정성 | Heartbeat, Reconnect |

### 반드시 구현할 내용

```text

```

### 핵심 구현 기술

## 5.2 Unreal Dedicated Server 프로그래밍

### 프로젝트 범위

- 콘텐츠 양보다 네트워크 흐름과 서버 권한 구조에 집중

### 네트워크 모델

```text

# 7. 게임 패치와 서버 배포 기초

게임 서버 프로그래머가 DevOps 전문가 수준의 배포 시스템을 직접 구축할 필요는 없지만, **빌드 결과물이 어떻게 서비스 서버와 클라이언트에 전달되는지는 이해해야 한다.**

## 7.1 게임 서버 배포

  ↓

  ↓

  ↓

  ↓
교체
  ↓

  ↓

```

---

## 7.2 게임 클라이언트 패치와 CDN

게임 클라이언트 패치는 일반적으로 **HTTP/HTTPS 기반 다운로드**를 사용한다.

```text
Build Server
    ↓
Patch File / Manifest
    ↓
Origin
    ↓
CDN
    ↓
HTTPS GET
    ↓
Game Launcher / Client
```

### 다운로드 프로토콜
- HTTP/1.1
- HTTP/2
- HTTP/3
- 실제 서비스에서는 HTTPS가 기본

FTP를 주력 게임 패치 프로토콜로 사용하는 방식은 현재 기준으로 일반적인 선택이 아니다.

### 게임 런처가 처리하는 것

```text
Manifest 다운로드
       ↓
로컬 버전 비교
       ↓
필요한 파일 결정
       ↓
HTTPS 다운로드
       ↓
Hash 검사
       ↓
패치 적용
```

### 대용량 파일
HTTP Range Request를 이용하면:
- 이어받기
- 부분 다운로드
- 대형 파일의 특정 구간 다운로드

가 가능하다.

### 과정 범위
학교에서는 다음 개념만 이해하면 충분하다.

- HTTP/HTTPS 파일 다운로드
- CDN / Origin 개념
- Manifest
- Version
- Hash
- Range Request
- Cache / Invalidation 개념

CDN 구축 자체는 교과과정의 핵심에서 제외한다.

# 10. 목표와 네트워크 모델의 관계

| 목표 | 네트워크 모델 | 교육적 의미 |
|---|---|---|

| **P2P (옵션)** | 기초 비교·실습 | 네트워크 모델 전체 이해를 위한 보완 |

즉 전체 과정의 주력은 **Authoritative Client/Server 게임 서버**이다.

P2P는 게임 네트워크의 한 축으로 반드시 이해하지만, MMORPG 서버 취업 목표를 흐리지 않도록 별도 대형 프로젝트로 만들지 않는다.
