# NCS 기준 검토: 정보통신·문화콘텐츠

검토일: 2026-11-05
대상: 이 폴더의 1~6장 원고
요청: NCS 기준(정보통신, 문화콘텐츠)으로 교재 내용에 부족함이 없는지 검토

## 결론

- 주제로 보면 이 교재는 NCS 문화콘텐츠의 '게임 서버 프로그래밍', '게임 DB 프로그래밍'과 직접 겹치고, 정보통신 응용SW엔지니어링의 '서버프로그램 구현', '데이터 입출력 구현' 등과도 겹친다.
- 검토 전 원고에서 NCS 쪽에 비해 비어 있다고 판단한 주제는 시험, 빌드와 배포, 서버 보안·운영 점검, 개발 환경·형상 관리·진단 도구, DB 모델링(ERD·정규화)과 SQL 응용·DB 내부 로직, 배치 작업, 라이선스·개인정보·법규였다. 이를 1장(1.10절, 1.11절), 5장(5.8.4절, 5.15절, 5.16절), 6장(6.11.6절, 6.11.7절, 6.13~6.16절)에 보강했다.
- 보강한 뒤에도 "NCS 능력단위를 충족한다"고는 쓸 수 없다. NCS는 능력단위마다 수행준거와 지식·기술·태도를 정해 두는데, 이번에 그 원문을 읽지 못했다. 이 문서에서 "대응"은 능력단위 이름과 교재 주제가 겹친다는 뜻일 뿐이다.
- 2~4장(엔진별 서버)에는 NCS 때문에 더한 내용이 없다. 이유는 '남은 부족과 범위 밖' 절에 적었다.
- Google Docs 문서는 고치지 않았다. 이 문서와 보강한 내용은 모두 이 폴더의 Markdown에만 있다.

### 확인하지 못한 것

- NCS 공식 사이트(ncs.go.kr)는 자동 접근이 막혀 있어 읽지 못했고, 우회하지 않았다. 그래서 능력단위의 수행준거, 지식·기술·태도의 원문과 현재 적용 중인 개정 버전을 확인하지 못했다. 위 논문들은 2018~2019년 자료여서 이후 개정이 있었을 수 있다.
- 게임 서버 프로그래밍과 게임 DB 프로그래밍 능력단위의 능력단위요소와 수행준거를 보지 못했다. 따라서 "수행준거 몇 번을 충족한다"는 판정은 하지 않았다.
- DB엔지니어링, 정보보호관리·운영, 네트워크구축 세분류에 속한 능력단위의 이름을 확인하지 못했다. 이 세 곳은 주제로만 비교했다.
- 시험에 해당하는 응용SW엔지니어링 능력단위는 표 2에 구버전 이름('개발자 테스트', '애플리케이션 테스트')만 나와서 현행 이름을 확인하지 못했다. 표 2에서 "애플리케이션 리팩토링 외 12 능력단위"로 뭉뚱그린 12개의 이름도 모른다.
- 이 밖의 세분류(정보기술개발의 다른 세분류, 정보보호와 통신기술의 다른 세분류)는 조사하지 않았다.

## 능력단위와 교재 절의 대응

판정은 세 가지만 쓴다. "직접 대응"은 이름이 가리키는 주제를 교재가 본격적으로 다룬다는 뜻이고, "부분 대응"은 일부만 다룬다는 뜻이며, "대응 없음"은 다루지 않는다는 뜻이다. 모두 이름과 주제를 기준으로 한 판정이다.

### 문화콘텐츠: 게임콘텐츠 제작

- 게임 서버 프로그래밍 (Game server programming)
  - 직접 대응. 1.2절, 1.4~1.9절(서버 분류와 구조, 전송 프로토콜, 패킷 설계, 실행 모델, 보안, 운영), 2~4장(엔진 위의 서버), 6.3~6.12절(Asio 서버, 분산 구성, 성능), 6.13~6.15절(시험, 배포, 보안·운영: 이번에 보강).
- 게임 DB 프로그래밍 (Game DB programming)
  - 직접 대응. 5장 전체. 이번에 보강한 곳은 5.8.4절(ERD·정규화), 5.15절(SQL 응용, 프로시저·트리거), 5.16절(배치)이다. 6.7절에서 서버와 DB를 연동한다.
- 게임 개발 관리 (Game development management)
  - 부분 대응. 1.10.1절(개발 환경), 1.10.2절(Git), 6.13절(시험), 6.14절(빌드와 배포). 일정·인력·위험 관리와 협업 절차는 다루지 않는다.
- 게임 플랫폼 프로그래밍 (Game platform programming)
  - 부분 대응. 4장이 PC 플랫폼인 Steam의 세션과 네트워킹을 다룬다. 콘솔·모바일 플랫폼은 범위 밖이다.
- 게임 엔진 프로그래밍 (Game engine programming)
  - 부분 대응. 2장(Unity)과 3장(Unreal)이 엔진의 네트워킹 부분만 다룬다. 렌더링, 물리, 입력 같은 엔진 전반은 범위 밖이다.
- 게임 서비스 운영 (Game Service operation)
  - 부분 대응. 1.9절, 1.11절, 6.14절, 6.15절이 로그, 지표, 배포, 개인정보·법규, 점검 항목을 다룬다. 점검 공지, 이벤트 운영, 고객 응대 같은 라이브 운영 업무는 다루지 않는다.
- 게임 알고리즘 (Game algorithm)
  - 대응 없음. 서버 쪽 알고리즘으로 게임 루프(1.7.1절)와 속도 제한(6.15.2절)이 나오지만 알고리즘 능력단위를 대신하지는 않는다.
- 게임 웹 프로그래밍 (Game Web programming)
  - 대응 없음.
- 그 밖의 능력단위(기획, 그래픽, 사운드, UI/UX 프로그래밍, AI, 그래픽 프로그래밍, 사업 기획)는 이 과목의 범위가 아니다.
- 참고: 권용만 논문의 표 5는 엔진 프로그래밍, 웹 프로그래밍, 서비스 운영을 교육과정에 반영하지 않은 것('N')으로 표시한 것으로 읽힌다. 표를 도구로 읽은 결과이므로 원문 확인이 필요하다.

## 남은 부족과 범위 밖

2~4장은 Unity NGO, Unreal Dedicated Server, Steam Listen Server 위에서 채팅 프로그램을 만드는 장이다. 엔진 프로그래밍과 플랫폼 프로그래밍 능력단위는 이름으로 보아 엔진·플랫폼 전반을 다루므로(수행준거는 확인하지 못했다) 네트워킹에 한정한 이 장들의 범위를 넘는다. 그래서 NCS 때문에 이 장들에 더한 내용은 없다.

- 게임 서비스 운영의 라이브 업무(점검 공지, 이벤트, 고객 응대, 신고·제재 처리)와 운영 도구는 다루지 않는다. 이름으로 보아 게임 웹 프로그래밍과 서비스 운영 능력단위의 영역이다.
- 컨테이너 배포, CI 서비스의 설정, 클라우드 배포는 범위 밖이다. 6.14.7절은 CI가 실행할 명령까지만 다룬다.
- 요구사항의 수집·분석과 설계 문서 작성(UML 등)은 다루지 않는다. 이 교재의 실습은 요구사항이 주어진 상태에서 시작한다. 넣는다면 6장에 서버 설계서를 쓰는 절을 추가하는 방법이 있다.
- 리팩토링, 엔진 전반, 알고리즘, 웹, 그래픽, 사운드, 기획은 범위 밖이다.
- 네트워크 장비와 회선의 구축은 범위 밖이다.
- DB 복제와 샤딩은 개념 수준이다.
- Windows에서 서버를 서비스로 등록하는 방법은 세 가지를 설명하는 데 그치고(6.14.5절) 예제와 실습은 없다.

### 확인하지 못한 것

## 저자가 정할 항목

각 항목에는 지금 적용해 둔 처리를 적었다. 바꾸고 싶으면 알려 주면 된다.

- 범위 문장과 6장의 충돌. 1.1.4절 원문은 "Linux 서버 운영, 컨테이너 배포, CI/CD는 본문의 범위에 넣지 않는다"고, 1.9절 원문은 "Linux 서버 운영 도구까지 다루지 않는다"고, 6.15절 도입의 '서비스화' 항목은 "컨테이너 배포와 CI/CD는 이 교재의 범위 밖이다"라고 쓰고 있다. 그런데 6.14.5절(systemd), 6.14.6절(롤링 교체와 롤백), 6.14.7절(CI 명령)이 들어 있다. 처리: 원문은 그대로 두고 1.1.4절과 1.9절 뒤에 "[NCS 검토에서 추가한 점]" 문단을 붙여 어디까지 다루는지 밝혔다. 선택지는 그대로 두기(현재), 원문 문장을 저자가 직접 고치기, 6.14.5~6.14.7절 빼기이다.
- 알 수 없는 패킷 종류. 1.6.3절 원문은 "연결을 끊지 않고 무시하거나 기록한다"인데, 6장의 서버(`IsValidHeader`)는 알 수 없는 종류를 받으면 연결을 닫는다. 처리: 6.15.3절 끝에 두 정책이 갈리는 기준(상대의 버전을 확인했는가, 새 버전과 옛 버전이 오래 섞이는가)을 설명하는 문단을 넣었다. 1.6.3절은 그대로이다.
- 로그와 개인정보. 1.9절 원문은 "개인정보와 비밀번호는 남기지 않는다"인데, 공격 대응을 위해 접속 IP는 남긴다. 처리: 1.11.2절과 6.15.5절에서 IP 주소를 남기되 개인정보처럼 다루게(접근 제한, 보관 기간, 필요 이상이면 가림) 했다. 1.9절은 그대로이다.
- 법규 서술(1.11절). 확률형 아이템 정보 공개의 시행일(2024년 3월 22일)과 아동 개인정보의 법정대리인 동의 조문(개인정보 보호법 제22조의2)은 검색 결과의 제목과 기사 수준에서 일치함을 확인했을 뿐 법령 원문은 읽지 못했다. 위반했을 때의 조치는 확인하지 못해 쓰지 않고 "법령으로 확인"하도록만 적었다. 본문에도 서비스 전에 원문을 확인하라는 문구를 넣었다.
- 분량. 6장이 약 3.1배가 되었다. 수업 시간에 비해 많으면 6.13.4절과 6.14.2절을 읽기 자료로 돌리거나 뺄 수 있다. 추가한 절은 독립된 절이라 빼기 쉽지만, 다른 곳에서 절 번호로 참조하므로 함께 고쳐야 한다.
- 이번 보강 전체. 1·5·6장의 추가는 모두 새 절과 새 문단, 새 연습 문제여서 원문과 구분된다. 저자의 범위 판단과 다르면 통째로 뺄 수 있다.
